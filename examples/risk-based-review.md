# 按风险安排审查

以下均为合成教学案例，不是工具执行日志或真实业务规则。技能不限语言或领域。

## 小任务不增加固定角色

请求：只修正 CLI 帮助文本里的拼写，参数、默认值和解析行为不变。

主智能体核对实际 diff，并检查帮助输出或已有对应测试即可。除非用户另有要求，不创建固定的“实现 + 独立审查 + 测试”团队。若实际发现解析逻辑也被修改，先核对范围和风险，不能因为任务标题写着“拼写”就直接通过。

## 高风险模块与无关任务继续并行

请求：按已澄清规则修复优惠券计算边界，同时更新独立的 CLI 使用文档；两项文件不重叠。

示例规则：金额用整数分；满 10000 分减 1000 分；订单创建调用计算模块。本规则仅供演示，不是通用优惠券约定。

| 阶段 | 主智能体动作 | 不受影响任务 |
| --- | --- | --- |
| 契约确认 | 核对金额规则、接口和验收条件，记录契约 C1 | 文档任务可按自身已满足的输入推进 |
| 实现提交 | 计算模块 A 提交候选 S1；金额结果变化需独立审查 | 文档 B 不等待 A 的审查 |
| 审查派发 | 给非实现者 R 提供用户规则、C1、基线与 S1 差异、实际测试证据及未验证项 | 主智能体可先验收已提交的 B |
| 发现问题 | 假设 R 发现门槛使用 `>`，10000 分不享受优惠；主智能体核对证据，退回 A | B 的有效结果不作废 |
| 修复复查 | A 提交 S2、S1→S2 差异及 9999/10000/10001 边界证据；R 定向核对原问题和影响点 | 无关内容不重跑 |
| 主验收 | 问题关闭、证据对应 S2 后才将 A accepted | B 不需要等 A 才 accepted |
| 整体集成 | 连接真实订单调用与最终计算模块，核对金额传递、错误行为和已澄清规则 | 不用替身单测冒充联调 |

S1/S2 是教学快照标识；真实任务必须给出可复核标识和实测输出。R 的“可供主验收”不是最终 accepted；主智能体不得为了启动 R 先把 A 标为通过。

## 证据缺失或候选变化

- 只有“测试通过”一句话，没有命令、结果和对应版本：补齐可核验材料，不能认定已验证。
- 审查的是 S1，但工作区已经变成 S2：原结论只覆盖 S1；主智能体检查差异，重验受影响部分。
- 修复顺带改了共享接口：不再是仅复查门槛条件，先协调契约和受影响执行者，再扩展复查与集成。
- 独立审查资源不可用：可以继续自查或无关工作，明确高风险验收关卡尚未满足，不虚构审查者或通过记录。
- 用户只要求审查：交付问题和证据，不直接修复；用户只要求设计：检查设计风险，不实现上述计算逻辑。

## 可观察的检查点

评估时检查是否正确选择审查强度、是否绑定实际候选和证据、是否保留主验收门槛、是否对修复做定向复查、是否仍进行必要集成。单纯出现“独立审查”字样不能证明行为正确；真实运行、静态检查和场景推演要分别记录。
