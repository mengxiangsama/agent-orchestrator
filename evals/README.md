# 行为评估方法

以下评估与静态包检查、JSON 记录检查分开。Skill 不因 Markdown 中写了“必须验收”就被视为已经正确执行。

## 场景与可观察结果

| 场景 | 输入 / 测试布置 | 检查真实结果 |
| --- | --- | --- |
| 简单任务 | 单行文本处理 | 结果正确，不进行不必要委派 |
| 两个独立任务 | 不相交写入范围、无依赖 | 真实创建两个执行者、均有交付，主智能体分别验收 |
| 设计后实现 | 合成优惠券金额函数 | 先得到设计并验收，再发出含设计版本的实现任务；测试验证实现 |
| 不合格返工 | 在隔离夹具中注入一个错误交付 | 主智能体检测失败，发送具体问题和标准，复测后才接受 |
| 失败/缺少能力 | 注入执行失败；另设无委派权限场景 | 不把失败当完成，有限处理并说明降级 |
| 只设计 | 现有合成业务代码 + 设计请求 | 有设计文档，原业务文件哈希不变 |

独立前向测试只给执行者 Skill、真实风格的用户请求和最小原始资料，不提供评分答案或预设结论。能力限制和隔离范围可以明确给出，但不能把“正确行为”提示给被评估者。主智能体读取实际文件、执行验证命令，而不是照抄执行者自报结果。

## 可复现性与限制

- [验证报告](reports/validation.md) 记录本次环境、日期、真实运行/故障注入/文档检查的区别。
- 确定性状态反例在 `tests/`，可无模型、无网络执行。它们不是对子智能体行为的替代验证。
- 真实模型运行不保证逐字复现；要重新进行行为评估，需要有授权的模型和真实子智能体工具。
- 临时评估工作区不进入发布包。仅把脱敏的小型设计、代码、测试和摘要复制到报告资料中；移除本机专属路径和任何凭证。
- 一次通过不代表所有模型、客户端、并发规模、生产项目或进程重启恢复都已验证。
