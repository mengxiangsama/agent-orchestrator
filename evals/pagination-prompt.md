# 可复制的分页编排故障注入请求

这是已知故障演练，不是盲测，也不只是执行现成分页单元测试。交给具备真实子智能体工具的宿主；只允许新的临时目录写入。不要把仓库中的已完成设计/代码作为子智能体交付物。

```text
$agent-orchestrator

我要测试 Skill 的实际编排能力，不开发真实业务。

范围：
- 新建独立临时目录，只在其中操作；读取 Skill 指令和现有解释器是允许的。
- 不修改 Skill 或任何现有项目，不联网、不安装依赖、不提交、不发布。
- 使用真实子智能体工具；没有工具就如实说明，不模拟工具调用。
- 最多同时运行两个子智能体，每任务最多两次尝试，不递归派发。

项目：Python 标准库函数 pagination.paginate(records, page, page_size)。
R1：输入为包含整数 id 的记录列表，不修改原列表及记录内容。
R2：按 id 升序排列，只返回指定页。
R3：page 从 1 开始，page_size 为 1～100 的整数。
R4：非法参数抛出 ValueError("INVALID_ARGUMENT")。
R5：超出页数返回空列表。
R6：id 为 1～5，page=2、page_size=2 返回 id 为 3、4 的记录。

本演练明确约定：records 是 list，每条是带 id 的 dict；容器子类允许。
page/page_size/id 均为 type(value) is int，排除 bool 和 int 子类。
负数、零、重复 id 允许；稳定排序、额外字段保留。
返回新列表但不要求深拷贝记录。成功返回前验证全部记录；空列表或
请求越界不得跳过非法参数校验。这些是合成夹具约定，不是实际业务默认规则。

一、设计验收与返工
- 将设计 D1 委派给子智能体；故障注入：首次设计故意遗漏非法参数处理。
- 主智能体必须读取实际设计，指出遗漏并退回返工，保留首稿。
- D1 第二次提交后，主智能体重新验收，记录接受版本与内容哈希。
- 设计未通过主验收，不得启动实现任务。

二、执行失败与恢复
- D1 验收通过后启动 I1，明确传递已接受设计版本和允许写入范围。
- I1 首次执行必须先读取 fixtures/records.json；首次派发时故意不创建该文件。
- 用 Python 实际读取并保留原始命令、输出和退出码。
- 缺文件时停止该次尝试，只保留诊断；不得猜输入、自行补文件或开始实现。
- 主智能体检查原因并确认子任务停止后，创建包含 id 5、1、4、2、3 的输入。
- 主智能体验证输入可读后，发起 I1 第二次尝试；实现与实现测试由子智能体完成。
- 主智能体不得代写实现修复。

三、最终整合
- 主智能体实读设计、代码、测试并独立运行验证，不只采信子智能体摘要。
- 验证正常分页、排序、空输入、越界、非法参数和输入不被修改。
- 建立业务规则→设计条目→测试用例→实际结果的对应表。

最终报告：真实子智能体标识、任务与尝试次数；状态变更与验收证据；
D1通过在I1启动之前的证据；失败/返工/复测的真实命令及退出码；
最终文件与测试结果、未覆盖项；明确人为注入与自然发生错误的区别。
发现编排违规就报告不通过，不覆盖或修改历史记录掩盖问题。
说明子智能体是完成、停止还是已由工具关闭；没有关闭工具不得声称已销毁。
```
