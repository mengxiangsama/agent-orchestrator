# 分页编排实测：用户规则与测试范围

本项目仅用于 agent-orchestrator 故障注入演练，不属于 现有项目 业务。

## 业务规则（R1—R6）

- R1：输入为包含整数 id 的记录列表，不修改原列表。
- R2：按 id 升序排列，只返回指定页。
- R3：page 从 1 开始，page_size 为 1～100 的整数。
- R4：非法参数抛出 ValueError("INVALID_ARGUMENT")。
- R5：超出页数返回空列表。
- R6：id 为 1～5 时，page=2、page_size=2 返回 id 为 3、4 的记录。

测试接口约定：`pagination.paginate(records, page, page_size)`，实现文件 `pagination.py`，Python 标准库，无网络、安装、提交、发布。
整数按 Python 严格 int 解释，布尔值不作为页码、页大小或 id。records 为 list，每条记录为带 id 的 dict；负数 id、重复 id 不禁止。额外字段保留。不要求对返回值深拷贝；只要求调用过程不修改输入。非法参数包含输入结构及分页参数。

## 故障注入（明确非自然缺陷）

1. D1 首次设计故意遗漏非法参数的处理规则；必须真实提交，再由主智能体读文件退回。不得提前把它接受为设计。
2. I1 第一次先读取 `fixtures/records.json`，该文件故意不存在；真实命令失败后停止，仅保留诊断。主智能体核验后才创建该输入，第二次尝试继续。
