# 风险分级、独立审查与定向复查

按变更可能造成的实际影响选择审查强度，不固定每项任务都增加一个审查智能体。独立审查提供额外证据，最终范围判断、问题裁决和验收仍由主智能体负责。

## 何时需要独立审查

| 情况 | 安排 |
| --- | --- |
| 文案、排版、局部机械修改或易完整验证的小修复，无关键行为变化 | 主智能体直接核对实际差异和相应验证，不强制新建审查者 |
| 改变金额/计费结果、权限/身份边界、敏感数据处理、数据迁移/删除、并发一致性、关键共享契约等，错误会造成较大损失或广泛影响 | 由未参与该改动实现的审查者独立检查；聚焦具体风险，不做无边界全库审计 |
| 用户明确要求独立审查 | 在授权范围内安排，不以任务小为由省略 |
| 风险不清楚 | 先核对实际改动和影响面，再决定；关键业务规则不明确仍先询问，不用审查替代需求澄清 |

文件位置、行数或“支付”等关键词不是风险本身。同一小改动也可能触及权限或资金边界；支付目录里改注释也不必自动升级。风险判断记录具体原因即可，不强制打分表。

审查者可以是有能力且未参与该改动实现的现有子智能体，不要求不同模型，也不强制新建。正在承担写任务的执行者先完成或暂停其任务再接审查；不能让同一执行者同时承担互相干扰的职责。主智能体自己实现的高风险改动同样需要非实现者检查。审查者只读候选代码，可运行授权的非破坏性检查；输出放在回复或约定的报告位置，不顺手修代码、不递归派发。

没有独立审查工具、授权或可用资源时，说明具体缺口；可以先完成有价值的自查，但不能声称独立审查通过。关卡未满足的高风险成果不作为已验收输入交给下游；等待资源、交给获授权的独立人员，或报告部分完成/阻塞并请求方向，不能自行豁免用户要求。

## 审查包模板

主智能体按实际任务填写，确认资料可访问，不只转发实现者的“完成了”。小任务不生成整套文件；必要信息可直接放进自包含提示词。

```text
审查 ID / 对应任务及尝试：
模式与权限：只审查，不修改候选代码，不继续委派；报告位置。
用户需求与验收条件：实际要求、非目标、关键业务规则来源。
已验收输入：设计/接口契约的版本、内容或可访问路径。
候选与基线：两个可核验的提交/快照标识；包含未提交改动时提供文件清单与哈希。
实际差异：限定到本任务的 diff/补丁、新增/删除文件及必要调用上下文。
风险重点：本次为什么需要独立审查、影响范围、特别关注的边界。
测试证据：对应候选标识、命令、目录、退出码、关键输出/日志；真实依赖或替身、未验证项。
已有问题与复查范围：首次写无；复查给原问题 ID、修复差异与必须复测的行为。
环境与约束：可读材料、可运行检查、并发写入情况、时间/尝试预算、缺资料时如何返回。
要求返回：按下面的审查结果格式；不得自封主验收通过。
```

分支名或文件路径不代表稳定版本。审查期间冻结相关写入或提供可核对的独立快照；无关任务继续并行。测试、diff 和审查结论应绑定同一候选版本；内容变化后判定哪些证据仍适用，受影响部分重新测试和审查，不拿旧版本通过结论覆盖新代码。

审查者检查实际差异及必要上下文，不只复述实现报告。已有测试证据完整、可核验且对应同一内容时，无需为了审查身份重复全部测试；对缺证据、可疑结果、风险边界或修复影响点补检查。静态阅读、实际执行、基于已有证据的判断分别说明。候选或必要需求资料缺失时返回无法判断及缺失项，而不是“未发现问题”。

## 审查结果与主验收

```text
审查 ID / 实际审查者 / 对应任务尝试 / 候选标识：
需求符合度：逐项结果或明确缺口。
正确性与风险：差异、调用关系、关键边界、兼容性。
问题：稳定 ID、位置、触发条件、影响、证据、建议通过标准。
验证方式：本次运行结果 / 已核验的既有证据 / 静态检查 / 未执行及原因。
复查结果：原问题逐项关闭、仍存在或无法确认；新增问题另列。
建议：可供主验收 / 需要修改 / 无法判断；非最终 accepted。
```

主智能体核对问题证据，区分阻塞缺陷、非阻塞建议和误报。真实缺陷未解决或关键要求无法验证时不验收；不采纳建议或认定误报也要给出依据，不能仅以“测试绿了”或预算耗尽结案。独立审查是 `submitted` 期间的验收子步骤，不改变下游必须等待 `accepted` 的规则。记录边界见 [任务记录](ledger.md)。

## 修复后的定向复查

1. 主智能体给责任执行者发送问题 ID、证据、允许修改范围和通过标准，按原任务剩余预算返工；其他不受影响任务继续。
2. 修复提交提供新候选标识、修复差异和对应测试证据。原审查者优先复查，也可换成另一名非实现者并完整交接，不把实现者自查称为独立复查。
3. 复查覆盖原问题、修复引入的新问题和受影响的接口/回归用例；不无故重查未变内容。修复改变契约、权限边界或影响面扩大时，扩展审查并按既有变更流程重验相关任务。
4. 主智能体确认问题关闭且必要证据齐备后才验收。复查不额外赠送实现尝试次数；因审查失败重新分配也不重置原预算。
5. 模块验收与复查完成后，仍在最终组合版本上做必要的整体集成检查，使用真实模块核对交互；单元测试、审查通过或替身验证不替代联调。环境不足时单列未验证项。

流程示例和边界反例见 [按风险审查示例](../examples/risk-based-review.md)。
