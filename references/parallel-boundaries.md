# 协作边界与并行

适用于多个模块、方法、服务或其他交付物协作，不限前端/后端，也不要求拆成微服务。简单任务仍直接完成；不要为了并行制造无必要的架构、文件或角色。

保持**一个主智能体统一调度多个子智能体**：主智能体决定边界、派发、验收、返工和集成；子智能体只执行分配的任务并返回证据。跨任务问题交给主智能体协调，不自行指挥其他执行者、继续拆派或替别人验收。并行的是执行，不是指挥权。

## 判断真正的依赖

区分三件事：**约定依赖、实现依赖、集成依赖**。最终运行时 A 调用 B，不代表开发 A 必须等待 B 的实现完成。

- 本任务只需知道对方的输入输出和行为，就能完整实现并用契约测试验证：依赖已验收的契约，不依赖对方实现；写入范围不冲突且工具资源允许时并行。
- 本任务确实需要前置产出的代码、生成文件、实测结果或尚未确定的业务决策：保留真实依赖，等对应成果验收；可将不依赖它的部分先分出执行。
- 需要检查多个真实成果一起工作：单列集成任务，依赖相关实现均已验收。不要把这个依赖提前施加到各模块开发阶段。

按已就绪任务调度，而不是固定“先前端再后端”“先优惠券再订单”或等整批任务全部完成。若改为串行，说明实际原因，如只有一个执行槽、共享文件冲突、缺少必要契约；不要把工具限制包装成业务依赖。

## 主智能体先统一最小协作契约

优先复用项目现有约定和已验收设计，必要时补足到足以独立实现即可。契约可以是简短说明、接口定义或类型文件，不强制新增完整设计文档。关键业务规则不明时先询问，不能让两个执行者分别猜测。

按任务类型明确适用项：

| 边界 | 必要约定示例 |
| --- | --- |
| 方法 / 模块 | 调用名称与签名、输入输出类型和字段、错误语义、副作用、谁负责哪些业务规则 |
| HTTP / 消息 | 地址与方法或消息结构、参数位置、必填/默认/空值、返回字段类型、错误与权限边界 |
| 数据 / 文档 | 输入与输出格式、字段或章节的含义、交付位置、版本及兼容要求 |
| 共享语义 | 按实际需求明确 ID 表示、金额或时间单位、精度、规则适用范围；不凭空引入新规则 |

主智能体验收后标记版本，将相同契约及必要内容发给各执行者。共享接口、类型文件、生成文件和公共测试设施指定单一写入负责人；模块的实现与测试划分到不重叠文件。现有结构确需修改同一文件时，主智能体统一集成或串行编辑，不允许互相覆盖。

## 各自完成本任务，不代做对方

执行者负责自己范围内的完整实现、异常与边界处理、验证证据，不以“对方尚未完成”为由留下本可完成的空实现。其完成标准写在任务提示词里，不是泛泛的“保证没问题”。

消费方可按已验收契约使用模拟数据、测试桩或替身完成自身验证；提供方按同一契约验证自身实现。明确哪些证据使用了替身、真实实现的接入位置以及待联调项，不把假数据混进交付的正常业务路径。替身验证不了的数据库约束、事务、真实错误路径等留给相应集成检查。

发现契约缺项、不兼容或无法独立验证时向主智能体报告具体差异和影响，不擅改共享签名、复制对方业务逻辑或跨越写入范围“顺手修好”。主智能体协调契约变更及受影响结果失效；只有内部修复且契约不变时，不暂停或重跑不受影响的兄弟任务。

## 滚动验收与最后集成

1. 收到单个任务提交就检查真实交付物和单项证据，无需等其他独立任务。若验证需要读取仍在变动的共享产物，先确认稳定快照或协调写入，不能边冲突边验收。
2. 不合格只向相应执行者发送具体问题、证据和复测标准，按现有尝试预算返工；其他不受影响任务继续。合格就标记该**模块任务** accepted，不代表整个项目完成。
3. 推进所有已满足前置条件、资源和所有权要求的任务。集成任务则必须等其实际依赖的所有成果验收。
4. 集成时使用真实实现，核对调用/接口、字段与类型、共享业务规则及适用的成功/失败路径。发现内部缺陷派回责任模块；契约有误则先协调变更并重验受影响成果。
5. 如环境不足以联调，明确“模块已验收，集成未验证/阻塞”及缺什么条件，不能用模拟测试代替最终通过。

## 示例：同一后端的优惠券计算与订单创建

下面是合成的调度示例，不是执行日志或优惠券业务规则；不限定语言，也不新增服务边界。

| ID | 工作与所有权 | 前置 |
| --- | --- | --- |
| C | 主智能体统一计算方法的入参、结果字段、类型、错误，以及金额/资格等规则的职责；共享契约单一负责人 | 用户需求、已有实现与已澄清规则 |
| A | 优惠券计算方法及其单元测试；只写优惠券模块与对应测试 | C 的验收版本 |
| B | 订单创建及其单元测试；只写订单模块与对应测试，调用计算接口，测试中可使用契约替身 | C 的同一验收版本 |
| I | 主智能体连接真实计算模块与订单模块，检查金额传递、错误处理及请求范围内的整体行为 | A、B 均验收通过 |

C 验收后 A 与 B 同时推进。A 先交付就先验收 A；A 需要返工时 B 继续。B 先通过也无需等待 A 才记为模块验收通过；但 I 必须等双方通过。

若订单单测发现问题来自替身违背契约，修订单测试；若优惠券计算实现违背契约，返工 A；若契约本身漏了关键规则，主智能体澄清并更新契约，再重验受影响部分。不能互相甩给对方，也不能让两个智能体同时修改共享类型。

同理，前端与后端可共用已验收 API 约定并行，数据转换与消费模块可共用已验收数据格式并行。是否可并行取决于当前阶段的真实输入、验证能力和写入边界，不取决于角色名称。
