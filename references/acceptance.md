# 主智能体验收与最终报告

## 验收前

核对 task ID、尝试、前置验收版本和写入范围；取得交付物的真实路径/差异。工具报告完成、进程退出 0、主智能体验收通过是不同的事实。

## 验收记录模板

| 项目 | 主智能体应核对的证据 |
| --- | --- |
| 用户范围 | 分析/设计/审查未变成实施；实际变更未超出授权 |
| 内容存在 | 打开真实文件，检查 diff/文件列表，不只读摘要 |
| 单项质量 | 每条验收条件对应实际输出或测试结果 |
| 接口与业务 | 字段名、类型、单位、空值、错误、业务规则与已验收前置一致 |
| 跨任务关系 | 独立成果间无冲突/遗漏，没有使用已失效设计 |
| 验证证据 | 命令、目录、退出码和输出可核验；区分运行测试、静态检查、未执行 |
| 决定 | accepted + 版本，或 rework/blocked + 原因与标准 |

对代码至少执行风险相称的测试/构建/静态检查；最后做必要的集成验证。环境无法执行时如实记录，不将“看起来正确”升级为运行通过。

对设计检查需求覆盖、关键规则来源、依赖、接口、异常路径、未决问题和验收可实施性。业务规则未决的设计不得作为编码的已验收输入。

对审查交付可定位的问题、影响、证据及不确定性；不因发现问题就擅自修改。

## 最终报告模板

```text
结论：完成 / 部分完成 / 阻塞；与原始请求对应的成果。
交付物：实际路径/链接及用途。
调度摘要：是否使用子智能体、实际创建数量/任务、依赖和关键验收决定。
验证：实际运行的命令与结果；静态/文档检查另列；集成检查结果。
未验证：缺少的环境、权限、外部服务或未覆盖的平台。
限制/风险：仍然存在的问题，不夸大 Skill 的能力。
必要后续：需要用户决定的具体事项；没有则不制造确认步骤。
```

发布或部署只有用户授权且实际完成时才能报告。将“本地生成”“测试通过”“提交”“推送”“线上验证”分别表述。
